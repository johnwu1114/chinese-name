## Context

index.js 是唯一的程式檔，242 行，所有邏輯平鋪在一個檔案中。維持單檔、jQuery、無建置步驟的前提下進行結構重整。

現有結構：
- 第 1-7 行：全域變數宣告（混雜設定與狀態）
- 第 9-140 行：`$(function() {...})` 巨大匿名函式（事件綁定 + 資料載入）
- 第 142-191 行：工具函式散落
- 第 192-241 行：核心演算法 `getCombinations`

## Goals / Non-Goals

**Goals:**
- 依關注點將程式碼組織為清楚的區塊
- 消除名字第一字/第二字的重複渲染邏輯
- 改善變數命名可讀性
- 維持完全相同的功能行為

**Non-Goals:**
- 不引入模組系統或建置工具
- 不更換 jQuery
- 不改動 HTML 結構或 CSS
- 不改動 JSON 資料格式
- 不優化演算法效能

## Decisions

### 1. 維持單檔結構，用註解區塊分段

**選擇：** 用 `// ============` 風格的註解分隔區塊，不拆成多檔。

**替代方案：** 拆成 config.js / algorithm.js / ui.js 等多檔。

**理由：** 無建置工具，多檔需要在 HTML 手動加多個 `<script>` 且有載入順序問題。單檔 + 清楚區塊在此規模（<300 行）已足夠。

### 2. 區塊順序

```
// ==================== 常數與設定 ====================
// ==================== 核心演算法 ====================
// ==================== UI 渲染 ====================
// ==================== 事件處理 ====================
// ==================== 初始化 ====================
```

**理由：** 由底層到高層排列 — 先定義資料與演算法，再定義使用它們的 UI 和事件。初始化放最後，確保所有函式已定義。

### 3. 抽取共用函式 `renderNameChars(draw, data)`

**現況：** 第 72-89 行和第 92-107 行幾乎完全相同，只差 `val.middle` vs `val.bottom` 和 class 名稱前綴。

**做法：** 抽為 `renderNameChars(index, draw, zodiacData)`，用參數控制差異。`index` 為 1 或 2，對應 class 前綴 `giveName1_` / `giveName2_`。

### 4. 變數重新命名

| 現有 | 改為 | 理由 |
|---|---|---|
| `$81` | `eightyOneMap` | `$` 前綴暗示 jQuery 物件，數字開頭不直覺 |
| `$quality` | `QUALITY_THRESHOLD` | 常數應大寫 |
| `$api_url` | `API_URL` | 同上 |
| `$sancaiKey` | `SANCAI_ELEMENTS` | 更語意化 |
| `$pickWords` | `selectedChars` | 移除 `$` 前綴，更清楚 |
| `$chineseCharacters` | `charDictionary` | 精簡 |
| `$sancai` | `sancaiTable` | 區分變數與常數 |

### 5. 移除 `get81Content` 包裝函式

直接在 `renderResult` 中用 `eightyOneMap[draw].content`，省去無意義的中間層。

## Risks / Trade-offs

- **功能迴歸風險** → 重構前後用相同輸入（如姓氏「陳」、生肖「雞」）比對 DOM 輸出，確認結果一致
- **變數重新命名可能遺漏** → 全域搜尋確認無殘留舊名稱
- **區塊劃分主觀** → 以此設計文件為準，不做額外主觀調整
