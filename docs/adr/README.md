# 重要決策索引

## 1. 收錄門檻與核准流程

重要決策正文統一放在本目錄，一決策一檔。是否收錄，依下列面向判斷：

- 是否需要長期保留選擇理由。
- 是否影響模組邊界或契約。
- 翻轉成本有多高。
- 未來是否可能重新提案。

範圍包含架構、重大業務規則、契約及跨模組政策。這些項目用於判斷重要性，不自行增加四項皆成立的門檻。一般 bug fix、參數調整與日常實作不逐項收錄；工作日誌、試錯與進度屬歷史過程。

**核准流程：由 John Wu 核准。** John Wu 於 2026-11-19 確認此流程。新 ADR 先標「提案」，John Wu 同意後才改成「接受」。翻轉既有決策同樣需要 John Wu 同意。

一般任務不主動讀取本目錄正文。只有決策、明確追溯或現況指定依據需要時，才開必要的索引與相關單篇。現況以[架構](../architecture.md)等現況文件為準。

## 2. 編號、欄位與維護

- 檔名使用四位數編號加小寫 dash 主題，例如 `0001-decision.md`。
- 取現有最大編號加一。不重用或回填廢棄編號。並行新增時，合併前檢查數字前綴唯一，不能只比較完整檔名。
- 每份 ADR 包含：狀態（提案／接受／否決／已取代）、日期、背景與問題、決策、真實考慮過的替代方案、理由與後果及限制、相關文件與取代關係。
- 保留真實日期、舊識別、來源及核准依據。未知明說，不以整理日期冒充決策日期，也不虛構替代方案。
- 翻轉時新增 ADR，舊份標示已取代，雙向連結並更新索引與受影響現況。部分取代須明示範圍及仍有效部分。
- 索引欄位固定為編號、標題、狀態、日期、舊識別與取代關係。有紀錄時連到實際檔案。
